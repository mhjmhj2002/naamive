---

# 1. Objetivo

Definir o conteúdo mínimo identificável da Business Baseline produzida por
Project.ARCHITECTURE.

---

# 2. Conteúdo conceitual

Pode incluir:

```text
Conception Baseline ref
Project version
Module identities/versions
Module responsibility map
boundaries
dependencies
integrations
conceptual contracts
data ownership
cross-cutting requirements
architecture decisions
Technology Baseline ref/version
risks/findings
open classified questions
evidence/review/audit refs
```

---

# 3. Identidade

Deve ser possível identificar exatamente:

```text
qual arquitetura foi considerada válida para PLANNING?
```

---

# 4. Não exige entidade física nominal

A implementação pode materializar essa baseline por composição determinística ou
registro próprio.

O nome físico não é normativo.

---

# 5. Supersession

Mudança material de arquitetura produz nova baseline ou composição equivalente,
preservando anterior.

---

# 6. Relação com Technology Baseline

Technology Baseline é artefato arquitetural referenciado pela Architecture
Baseline.

Não é sinônimo da Architecture Baseline.

---

# 7. Relação com PLANNING

PLANNING deve consumir Architecture Baseline identificável.

Não pode reconstruir arquitetura a partir de chats/arquivos soltos.
