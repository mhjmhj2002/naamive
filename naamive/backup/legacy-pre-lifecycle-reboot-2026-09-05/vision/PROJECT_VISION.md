# NAAMIVE

> Transforming Business Needs into Delivered Software.

## Propósito

NAAMIVE existe para transformar uma necessidade de negócio em um produto de software completo e entregue.

Sua missão não é gerar código, orquestrar agentes de inteligência artificial ou automatizar atividades isoladas de desenvolvimento. Sua missão é reduzir a distância entre um problema real de negócio e uma solução de software entregue.

O software é a consequência. O valor de negócio é o objetivo.

## Princípio central

Tudo começa com uma necessidade de negócio. Toda decisão produzida pelo projeto deve ser rastreável até essa necessidade. A tecnologia nunca define o produto; o negócio define.

## Definição

NAAMIVE é uma plataforma de engenharia de software capaz de conduzir o ciclo completo de um produto. A plataforma começa com uma necessidade de negócio e termina somente quando a solução é entregue.

Todo o ciclo deve permanecer:

- rastreável;
- reproduzível;
- auditável;
- modular;
- evolutivo.

## Estrutura conceitual

O NAAMIVE possui uma plataforma global única. Ela contém os agentes, a governança, o runtime, a orquestração, os templates, os contratos, os schemas e as ferramentas utilizados para conduzir projetos.

Cada necessidade aprovada gera um projeto independente. Cada projeto pode gerar um ou mais módulos de negócio.

```text
Platform
    ↓
Business Need
    ↓
Project
    ↓
Business Modules
    ↓
Applications
    ↓
Validation
    ↓
Delivery
    ↓
Evolution
```

## Decomposição modular

Cada projeto é decomposto em uma ou mais capacidades de negócio. Cada capacidade se torna um módulo. Módulos são definidos por responsabilidade de negócio, nunca por tecnologia.

## Ciclo canônico

```text
Business Need
      ↓
Project Definition
      ↓
Business Analysis
      ↓
Domain Understanding
      ↓
Module Identification
      ↓
Architecture
      ↓
Planning
      ↓
Implementation
      ↓
Validation
      ↓
Delivery
      ↓
Evolution
```

Nenhuma etapa pode ser pulada implicitamente. Toda transição deve possuir evidência.

## Papel dos agentes

Os agentes são componentes globais da plataforma. Eles executam atividades de engenharia dentro dos limites definidos pela governança e pela autoridade humana. Eles não são o produto: são parte da força operacional do NAAMIVE.

Projetos não mantêm cópias independentes dos agentes globais.

## O que o NAAMIVE não é

NAAMIVE não é:

- um gerador de CRUD;
- um gerador de código;
- uma plataforma low-code;
- uma plataforma no-code;
- apenas um framework de IA;
- apenas um orquestrador;
- uma IDE;
- um projeto de demonstração;
- um laboratório de experimentos.

Esses recursos podem existir internamente, mas nenhum define o propósito do NAAMIVE.

## Estabilidade da visão

A visão do projeto é estável. A implementação pode evoluir. Mudanças conceituais profundas devem ser estudadas e validadas antes de serem incorporadas.

O repositório NAAMIVE é tratado como produto, não como laboratório experimental.

## Definição de sucesso

O sucesso do NAAMIVE não é medido pela quantidade de código, agentes ou automações. Ele é medido pela capacidade de transformar necessidades de negócio em produtos entregues, preservando:

- qualidade;
- rastreabilidade;
- modularidade;
- governança;
- capacidade de evolução.
